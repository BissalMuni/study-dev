# Docker 환경에서 Let's Encrypt 인증서 갱신

nginx를 Docker 컨테이너로 운영할 때 Let's Encrypt 인증서가 만료되면 certbot을 직접 실행할 수 없다.
이 문서는 certbot standalone 방식으로 인증서를 갱신하고 nginx에 적용하는 전체 과정을 정리한다.

## 상황

- nginx, frontend, backend, DB가 모두 Docker 컨테이너로 운영 중
- Let's Encrypt 인증서 90일 만료로 HTTPS 접속 불가
- nginx 컨테이너 내부에 openssl 없음 (alpine 기반)

## 1단계: 인증서 만료 확인

nginx 컨테이너에 openssl이 없으므로 호스트에서 직접 확인한다.

```bash
# nginx 컨테이너가 마운트한 ssl 폴더 경로를 동적으로 추출
openssl x509 -in $(docker inspect my-nginx \
  --format '{{range .Mounts}}{{if eq .Destination "/etc/nginx/ssl"}}{{.Source}}{{end}}{{end}}')/fullchain.pem \
  -noout -dates
```

출력 예시:
```
notBefore=Feb  9 03:16:07 2026 GMT
notAfter=May 10 03:16:06 2026 GMT  ← 만료됨
```

## 2단계: certbot standalone으로 갱신

certbot standalone 방식은 포트 80을 직접 점유한다.
nginx가 포트 80을 쓰고 있으므로 잠깐 내린 후 갱신한다.

```bash
docker stop my-nginx && \
docker run --rm \
  -v /etc/letsencrypt:/etc/letsencrypt \
  -v /var/lib/letsencrypt:/var/lib/letsencrypt \
  -p 80:80 \
  certbot/certbot renew --standalone && \
docker start my-nginx
```

> **핵심**: `-v /etc/letsencrypt:/etc/letsencrypt` — 호스트의 certbot 설정 디렉토리를 그대로 마운트해야 기존 도메인 설정을 인식한다.

성공 시 출력:
```
Processing /etc/letsencrypt/renewal/example.com.conf
Congratulations, all renewals succeeded:
  /etc/letsencrypt/live/example.com/fullchain.pem (success)
```

## 3단계: 새 인증서를 nginx ssl 폴더에 복사

갱신된 인증서는 `/etc/letsencrypt/live/` 에 저장된다.
nginx 컨테이너가 마운트하는 ssl 폴더에 수동으로 복사해야 한다.

```bash
SSL_DIR=$(docker inspect my-nginx \
  --format '{{range .Mounts}}{{if eq .Destination "/etc/nginx/ssl"}}{{.Source}}{{end}}{{end}}') && \
sudo cp /etc/letsencrypt/live/example.com/fullchain.pem $SSL_DIR/fullchain.pem && \
sudo cp /etc/letsencrypt/live/example.com/privkey.pem $SSL_DIR/privkey.pem && \
docker restart my-nginx
```

> `sudo` 가 필요한 이유: `/etc/letsencrypt/live/` 는 root 소유 디렉토리

## 4단계: 갱신 확인

```bash
echo | openssl s_client -connect localhost:443 -servername example.com 2>/dev/null \
  | openssl x509 -noout -dates
```

출력 예시:
```
notBefore=May 11 13:25:56 2026 GMT
notAfter=Aug  9 13:25:55 2026 GMT  ← 90일 갱신 완료
```

## 트러블슈팅

| 증상 | 원인 | 해결 |
|---|---|---|
| `port is already allocated` | nginx가 포트 80 점유 중 | `docker stop my-nginx` 먼저 |
| `No renewals were attempted` | certbot이 설정을 못 찾음 | `-v /etc/letsencrypt:/etc/letsencrypt` 확인 |
| `Permission denied` 복사 실패 | `/etc/letsencrypt/live/` 는 root 소유 | `sudo cp` 사용 |
| nginx에 openssl 없음 | alpine 기반 이미지 | 호스트에서 openssl 명령 실행 |

## 자동 갱신 설정 (권장)

매월 1일 새벽 3시에 자동 갱신하는 크론잡:

```bash
crontab -e
```

```
0 3 1 * * docker stop my-nginx && \
  docker run --rm \
    -v /etc/letsencrypt:/etc/letsencrypt \
    -v /var/lib/letsencrypt:/var/lib/letsencrypt \
    -p 80:80 certbot/certbot renew --standalone && \
  SSL_DIR=$(docker inspect my-nginx --format '{{range .Mounts}}{{if eq .Destination "/etc/nginx/ssl"}}{{.Source}}{{end}}{{end}}') && \
  sudo cp /etc/letsencrypt/live/example.com/fullchain.pem $SSL_DIR/fullchain.pem && \
  sudo cp /etc/letsencrypt/live/example.com/privkey.pem $SSL_DIR/privkey.pem && \
  docker restart my-nginx
```

## 핵심 정리

> certbot standalone은 포트 80을 직접 점유하므로 nginx를 잠깐 내려야 한다.
> 갱신 후 `/etc/letsencrypt/live/` 의 새 인증서를 nginx ssl 볼륨에 수동 복사해야 적용된다.
