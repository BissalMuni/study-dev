# Next.js MDX SSR 500 디버깅 — remark-gfm singleTilde가 만든 strikethrough 함정

`next-mdx-remote/rsc`로 MDX를 서버 렌더링하는 Next.js 14 + App Router 사이트가 일부 페이지에서 SSR 500을 일으켰다. 브라우저 콘솔에는 다음 한 줄만 보였고, 실제 에러 메시지는 가려져 있었다.

```
Error: An error occurred in the Server Components render.
The specific message is omitted in production builds to avoid
leaking sensitive details. A digest property is included...
```

## 증상의 모양 — Hydration 에러로 오해하기 쉽다

브라우저 콘솔만 보면 순수 hydration 문제처럼 보였다.

```
Uncaught Error: Minified React error #418
Uncaught Error: Minified React error #423
```

- `#418` — Hydration failed: 서버 HTML과 클라이언트 렌더 불일치
- `#423` — Hydration 도중 에러가 발생했지만 React가 복구

여기에 한국 사이트라 `darkreader`/번역 확장으로 인한 DOM 변형도 흔한 후보다. 실제로 처음에는 그쪽을 의심하며 `<html suppressHydrationWarning>`, AntdRegistry 누락 등을 살폈다.

## 결정적 단서: production은 메시지를 숨긴다

`#418`/`#423`은 *증상*이지 원인이 아니었다. 진짜 SSR throw는 React가 렌더 도중 끊어졌을 때 발생하며, prod 빌드는 메시지를 가리고 `digest` 해시만 노출한다.

진짜 메시지는 두 곳 중 하나에서만 보인다:

1. **Vercel Runtime Logs** — Dashboard → Deployment → Logs. `digest`로 매칭되는 stack trace가 평문으로 찍힘.
2. **로컬 `next dev`** — dev 모드에서는 풀 메시지가 콘솔로 흐름. (단, prod와 동작이 100% 같진 않음)

이번엔 Vercel 로그에 진짜 원인이 적혀 있었다.

```
[Error: [next-mdx-remote] error compiling MDX:
  Expected the closing tag </td> either after the end of strikethrough (106:87)
  or another opening tag after the start of strikethrough (105:88)
  More information: https://mdxjs.com/docs/troubleshooting-mdx]
{ digest: '62146265' }
```

## 위치 해석 — 왜 라인이 어긋나 보였는가

에러는 `<td>` 닫기 전에 strikethrough가 안 닫혔다고 했지만, 파일 105줄에는 `~`가 없었다.

```text
Line 105: <td style={{...}}>1.0%</td>
Line 106: <td style={{...}}>0.1%</td>
```

`next-mdx-remote`는 frontmatter를 떼고 본문만 MDX 파서로 넘긴다. Frontmatter가 15줄이었으므로 파서의 105 → 파일의 120이었다.

```text
Line 120: <td style={{...}}>1.1~3.3%</td>   <- 여기 ~
Line 121: <td style={{...}}>1.0~3.0%</td>   <- 여기 ~
```

두 셀에 각각 단일 `~`가 하나씩 있고, 둘 사이에 `</td><td>` 가 끼어 있다.

## 근본 원인: remark-gfm의 singleTilde 기본값

GitHub Flavored Markdown 표준 strikethrough는 `~~text~~` (이중 틸드)다. 그러나 `remark-gfm`은 기본 옵션이 `singleTilde: true`라서 `~text~` (단일 틸드)도 strikethrough opener로 인식한다.

수치 범위를 한국어 본문에서 자주 쓰는 `1.1~3.3%`, `2020.7.10~8.11`, `~2027.12.31` 같은 표현이 있는 셀에서는, 첫 `~`가 strikethrough를 열고 다음 줄 셀의 `~`를 closer로 짝지으려고 한다. 그 사이를 `</td>`가 가로지르니 MDX 파서는 "strikethrough가 닫히기 전에 `</td>`가 나왔다"며 컴파일 자체를 거부했다.

```text
<td>1.1~3.3%</td>      <-- ~  여기서 strikethrough 시작 (line 120 col 88)
<td>1.0~3.0%</td>      <-- ~  여기서 닫으려고 시도 (line 121 col 87)
                            그 사이 </td><td>가 있어서 fail
```

특이점:
- 한 줄에 `~`가 두 개여도 셀 안에 닫히면 그 셀 내부만 strikethrough가 되고 컴파일은 통과한다 (원치 않는 `<del>` 출력은 별개 문제).
- 한 줄에 `~`가 하나, 다음 줄에 또 하나, 라인 사이에 JSX 닫기/열기 태그가 있으면 SSR 자체가 죽는다. 이게 가장 위험한 패턴.

## 한 줄 fix — 콘텐츠 0줄 수정

해결책은 `remark-gfm`을 표준 GFM 모드로 되돌리는 것이다.

```typescript
// 출처: gangubuy-tax-new/components/content/MDXRenderer.tsx
import { MDXRemote } from 'next-mdx-remote/rsc';
import remarkGfm from 'remark-gfm';
import rehypeSlug from 'rehype-slug';

<MDXRemote
  source={source}
  components={mdxComponents}
  options={{
    mdxOptions: {
      remarkPlugins: [[remarkGfm, { singleTilde: false }]],
      rehypePlugins: [rehypeSlug],
    },
  }}
/>
```

플러그인 인자는 `[plugin, options]` 튜플 형태로 전달한다. `singleTilde: false`면 `~~text~~`만 strikethrough가 되고, 단일 `~`는 모두 리터럴 텍스트가 된다. 89개 단일 틸드를 가진 콘텐츠 14개 파일 모두 그대로 둔 채 SSR 복구.

## 대안: 콘텐츠 escape

콘솔이 평소 strikethrough를 일부러 쓰는 사이트라면 옵션을 끄는 대신 셀 안 `~`를 escape하는 패턴도 쓴다.

```mdx
<td>1.1&#126;3.3%</td>
```

`&#126;`은 ASCII 126 (`~`). MDX 파서는 HTML 엔티티를 해독해 텍스트로 통과시키므로, GFM 규칙에 걸리지 않는다. 단점은 14개 파일 89곳을 모두 손봐야 한다는 점.

## 디버깅 회고

이번 사건의 흐름을 한 줄로 묶으면:

> **production의 `#418` hydration 에러는 "원인"이 아니라 "잔향"이다. 진짜 SSR throw가 있었고, 그 메시지는 Vercel 로그에만 있었다.**

다음과 같이 접근해야 한다:

1. 콘솔에 React #418/#423만 보이고 SSR 500도 같이 떨어지면 → 원인은 SSR 쪽
2. `digest` 해시를 들고 Vercel Runtime Logs로 직행
3. 라인:컬럼이 어긋나 보이면 frontmatter 길이만큼 더해서 본문 위치로 환산
4. 콘텐츠 변경 vs. 파서 옵션 변경 — 영향 면적이 적은 쪽을 우선

## 부수 학습: Antd v6 + Next.js App Router

같은 사이트에서 함께 정리한 두 가지.

### AntdRegistry 누락 — CSS-in-JS 클래스 mismatch

Antd 6.x는 CSS-in-JS로 해시된 클래스명을 만든다. SSR 시 등록기를 안 쓰면 서버/클라이언트 해시가 어긋나 hydration 경고가 항상 한 박자씩 발생한다.

```bash
npm install @ant-design/nextjs-registry
```

```tsx
// 출처: gangubuy-tax-new/app/layout.tsx
import { AntdRegistry } from '@ant-design/nextjs-registry';

export default function RootLayout({ children }) {
  return (
    <html lang="ko" suppressHydrationWarning>
      <body suppressHydrationWarning>
        <AntdRegistry>
          <AntdProvider>{children}</AntdProvider>
        </AntdRegistry>
      </body>
    </html>
  );
}
```

### Antd v6 Alert prop 변경

v5의 `<Alert message>` → v6는 `message`도 받지만 내부적으로 `title` 슬롯에 매핑한다. 잘못된 prop을 주면 children이 사라지고 alert가 빈 박스로 렌더되지만 throw는 안 한다 — 조용히 깨지는 종류의 버그라 더 골치아프다.

```tsx
// 잘못 작성된 Callout (children이 사라짐)
<Alert title={children} type={typeMap[type]} />

// 정상
<Alert message={children} type={typeMap[type]} />
```

`typeMap`에 들어가지 않은 타입(`success`, `error`)을 prop으로 넘기면 `type={undefined}`가 되어 default(`info`)로 fallback. 시각적으로 깨진 것처럼 보이지만 SSR은 통과한다.

## 핵심 정리

> **Production의 막힌 React 에러는 `digest`만 보고 끝내지 말고 서버 로그까지 따라가야 한다. 콘텐츠가 멀쩡해 보여도 마크다운 파서 옵션 한 줄이 SSR 전체를 죽일 수 있다.**

- React `#418`/`#423`은 hydration 단계 잔향, 진짜 원인은 SSR throw
- `next-mdx-remote`는 frontmatter를 떼고 파서에 넘기므로 에러 라인은 본문 기준
- `remark-gfm`의 `singleTilde: true` (기본값)는 한국어 수치 범위 표기와 충돌
- 옵션 한 줄(`singleTilde: false`)로 콘텐츠 변경 없이 회복 가능
- Antd 6.x + Next.js App Router는 `@ant-design/nextjs-registry` 거의 필수
