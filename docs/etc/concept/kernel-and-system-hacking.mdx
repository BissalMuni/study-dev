# 커널 구조와 시스템 해킹 기초

컴퓨터를 깊이 이해하려면 OS 커널이 하드웨어를 어떻게 제어하고, 응용 프로그램과 어떻게 통신하는지 알아야 한다. 해킹/보안의 핵심도 이 경계에서 발생한다.

## 컴퓨터의 계층 구조

```
응용 프로그램 (Node.js, Chrome 등)
        ↕ 시스템 콜
      커널 (OS 핵심)
        ↕ 직접 제어
하드웨어 (CPU, 메모리, 디스크, 네트워크)
```

- **응용 프로그램**은 하드웨어에 직접 접근할 수 없다
- 반드시 **커널을 통해서만** 하드웨어 자원을 사용할 수 있다
- 이 요청을 **시스템 콜(System Call)**이라 부른다

## 커널이 제어하는 것

| 하드웨어 | 커널의 역할 |
|---------|-----------|
| CPU | 프로세스 스케줄링 (어떤 프로그램에 CPU 시간을 줄지 결정) |
| 메모리 | 할당/회수, 프로세스 간 메모리 격리 |
| 디스크 | 파일 시스템 관리 (읽기/쓰기) |
| 네트워크 | 소켓, 패킷 전송 |

## Windows의 계층 구조

Windows에서 시스템 콜은 여러 계층을 거친다:

```
응용 프로그램 (Node.js 등)
        ↕ 함수 호출
Win API (kernel32.dll, user32.dll) ← 라이브러리 (유저 모드)
        ↕
ntdll.dll (NtCreateFile 등)       ← 시스템 콜 래퍼
        ↕
커널 (ntoskrnl.exe)               ← 커널 모드, 하드웨어 직접 제어
```

- **Win API**: 개발자가 쓰기 쉽게 만든 함수들 (`CreateFile`, `ReadFile` 등)
- **ntdll.dll**: 실제 시스템 콜을 호출하는 중간 다리
- **커널**: 하드웨어를 직접 제어하는 핵심

Win API는 독립 실행 프로그램이 아니라, 응용 프로그램 안에 로드되는 **DLL(라이브러리)**이다. 커널 밖의 **유저 모드**에서 동작한다.

## 프로세스 간 통신 (IPC) — 파이프 예시

실제 프로젝트 코드에서 Node.js가 Claude CLI를 실행하고 파이프로 통신하는 사례:

```typescript
// 출처: gangubuy-tax-new/scripts/run-pipeline.ts
import { spawn } from 'child_process';

const proc = spawn('claude', [
  '-p', '-',
  '--output-format', 'text',
  '--allowedTools', 'Read,Edit,Write,Glob,Grep',
], {
  stdio: ['pipe', 'pipe', 'pipe'],
  //       ↑stdin  ↑stdout  ↑stderr
});

// Node → Claude CLI로 프롬프트 전송
proc.stdin.write(prompt);
proc.stdin.end();

// Claude CLI → Node로 응답 수신
proc.stdout.on('data', (data) => {
  stdout += data.toString();
});
```

### 파이프의 동작 원리

```
Node.js 프로세스          OS 커널           Claude CLI 프로세스
    │                    │                    │
    │── write() ──→  [메모리 버퍼]  ──→ read() ──│
    │                    │                    │
    │── read()  ←──  [메모리 버퍼]  ←── write() ──│
```

1. `spawn()`을 호출하면 OS가 **자식 프로세스**를 생성
2. OS 커널이 두 프로세스 사이에 **메모리 버퍼(파이프)**를 할당
3. 한쪽이 `write()` → 버퍼에 저장 → 다른 쪽이 `read()`로 수신
4. 프로세스끼리 직접 메모리를 공유하는 게 아니라, **커널이 중간에서 전달**

Node.js의 `child_process` 모듈이 내부적으로 C++(libuv)를 통해 OS 시스템 콜(`pipe()`, `fork()`, `dup2()`)을 호출한다.

### spawn vs exec

```typescript
import { spawn, exec, execSync } from 'child_process';
```

| 함수 | 특징 |
|------|------|
| `spawn` | 실시간 스트림 입출력 (데이터를 주고받으며 처리) |
| `exec` | 실행 끝나면 결과를 한번에 받음 |
| `execSync` | 동기 실행 (끝날 때까지 블로킹) |

## 보안/해킹 관점에서 커널의 중요성

커널은 모든 하드웨어 접근의 관문이기 때문에, 보안의 핵심 공격 지점이 된다:

| 공격 유형 | 설명 |
|----------|------|
| **메모리 익스플로잇** | 버퍼 오버플로우, use-after-free 등 — 메모리 관리 방식을 알아야 이해 가능 |
| **권한 상승** | 유저 모드 → 커널 모드 경계를 뚫어 관리자 권한 획득 |
| **루트킷** | 커널 레벨에서 악성 동작을 숨김 |
| **시스템 콜 후킹** | 커널과 앱 사이의 통신을 가로채 조작 |

## 학습 로드맵

단계를 건너뛰면 이해가 안 되므로 순서대로:

### 1단계: 컴퓨터 구조
- 📖 "밑바닥부터 만드는 컴퓨팅 시스템" (Nand2Tetris)
- CPU가 0과 1로 어떻게 동작하는지 직접 만들어봄

### 2단계: 운영체제
- 📖 "운영체제 아주 쉬운 세 가지 이야기" (OSTEP)
- 프로세스, 메모리, 파일시스템 설계 원리

### 3단계: C언어 + 리눅스
- 커널 코드를 읽으려면 C가 필수
- 리눅스에서 직접 시스템 콜 사용해보기

### 4단계: 리버싱/보안
- 바이너리 분석 (실행 파일이 어떻게 동작하는지)
- CTF 문제 풀기 (picoCTF 같은 초보용부터 시작)

## 핵심 정리

> 모든 프로그램은 커널을 통해서만 하드웨어에 접근할 수 있다. 해킹의 본질은 이 **경계(유저 모드 ↔ 커널 모드)**를 이해하고 취약점을 찾는 것이다. "왜?"를 계속 파고드는 습관이 가장 중요한 기초 체력이다.
