# LLM 로컬 실행 하드웨어 완전 가이드

로컬에서 LLM을 돌리려면 어떤 하드웨어가 필요한가? **모델 크기, 메모리 종류, 양자화, GPU/Mac/워크스테이션** 선택까지 한 번에 정리한 통합 가이드.

---

## 1장. LLM이 왜 하드웨어를 가리는가

### 1.1 LLM 동작 원리와 메모리 의존성

LLM은 수십억~수조 개의 **파라미터(가중치)**를 메모리에 올려두고, 입력 토큰마다 행렬 연산을 수행한다. 모델 전체가 빠른 메모리에 들어가야 실시간 응답이 가능하다.

### 1.2 "모델이 메모리에 다 들어가야 한다"의 의미

```
GPU VRAM (또는 통합메모리) ← 모델 가중치 + KV 캐시 + 작업 버퍼
                          모두 올라가야 빠르게 추론 가능
```

### 1.3 메모리 부족 시 무슨 일이 생기는가

- **Offload (오프로드)**: 일부 레이어를 시스템 RAM이나 SSD로 옮김 → 속도 5~50배 저하
- **OOM (Out of Memory)**: 아예 못 돌아가고 에러 발생

### 1.4 메모리 용량 vs 속도(대역폭)

| 자원 | 의미 | LLM에서 |
|---|---|---|
| **용량 (GB)** | 얼마나 큰 모델을 올릴 수 있는가 | 모델 크기 결정 |
| **대역폭 (GB/s)** | 메모리를 얼마나 빨리 읽을 수 있는가 | 추론 속도(t/s) 결정 |

→ **둘 다 중요**. 용량 부족 = 못 돌림 / 대역폭 낮음 = 답답하게 돌아감.

## 2장. 모델 크기와 메모리 — 비트 단위 이해

### 2.1 파라미터(B)와 메모리

`B = Billion` (10억). 7B = 70억 개 파라미터.

### 2.2 정밀도별 비트 사용량

| 포맷 | 비트 | 바이트 | 용도 |
|---|---|---|---|
| FP32 | 32 | 4 | 학습 표준 (구식) |
| FP16 / BF16 | 16 | 2 | 현대 학습·서빙 표준 |
| INT8 / Q8 | 8 | 1 | 추론 압축 |
| INT4 / Q4 | 4 | 0.5 | 로컬 LLM 표준 |
| INT2 / Q2 | 2 | 0.25 | 메모리 극부족 시 |

### 2.3 비트 → GB 환산 공식

```
필요 메모리 = 파라미터 개수 × 파라미터당 비트 ÷ 8 ÷ 1024³

예) 14B FP16:
14,000,000,000 × 16 ÷ 8 = 28,000,000,000 bytes
÷ 1024³ ≈ 26.1 GB
```

### 2.4 모델 크기별 원본 메모리

| 모델 | FP32 | FP16 | Q8 | Q4_K_M |
|---|---|---|---|---|
| 7B | 26 GB | 13 GB | 6.5 GB | 4.5 GB |
| 8B | 30 GB | 15 GB | 7.5 GB | 5 GB |
| 14B | 52 GB | 26 GB | 13 GB | 9 GB |
| 32B | 119 GB | 60 GB | 30 GB | 20 GB |
| 70B | 261 GB | 130 GB | 65 GB | 40 GB |
| 405B | 1,510 GB | 755 GB | 377 GB | 230 GB |

### 2.5 빠른 암기 공식

> - **FP16 메모리 ≈ 파라미터(B) × 2 GB**
> - **Q8 메모리 ≈ 파라미터(B) × 1 GB**
> - **Q4_K_M 메모리 ≈ 파라미터(B) × 0.6 GB**

## 3장. 양자화(Quantization) — 메모리 줄이는 기술

### 3.1 양자화란 무엇인가

학습된 모델의 가중치를 **더 적은 비트로 압축**하는 후처리 기술. 메모리 1/4~1/8로 줄이면서 품질은 95%+ 유지.

### 3.2 원리: 실수 → 정수 매핑

```
원본 FP32:  0.7234, -0.1239, 0.4523, ...
            ↓ 양자화 (그룹별 scale·offset 저장)
INT4:       5, -1, 3, ...

복원 시: 실제값 ≈ 양자화된값 × scale + offset
```

### 3.3 양자화 종류 비교 (Llama 3.1 8B 기준)

| 표기 | 평균 비트 | 파일 크기 | 품질 | 추천 |
|---|---|---|---|---|
| Q2_K | 2.6 | 3.2 GB | 큰 저하 | ❌ |
| Q3_K_M | 3.9 | 4.0 GB | 약간 저하 | △ |
| **Q4_K_M** | **4.85** | **4.9 GB** | **매우 좋음** | ⭐⭐ |
| Q5_K_M | 5.7 | 5.7 GB | 거의 원본 | ⭐ |
| Q6_K | 6.6 | 6.6 GB | 원본급 | 고품질 |
| Q8_0 | 8.5 | 8.5 GB | 원본 동일 | 메모리 여유 시 |

### 3.4 GGUF 표기법 읽기 — `Q4_K_M`

```
Q   4   _   K   _   M
│   │       │       │
│   │       │       └─ Medium (중요 레이어 한 단계 위 비트)
│   │       └───────── K-quants 방식 (현대 표준)
│   └───────────────── 4비트 기준
└───────────────────── Quantization
```

- `_S` (Small): 모든 레이어 균일
- `_M` (Medium): 중요 레이어(attention.wv, ffn.w2) 한 단계 위 ⭐
- `_L` (Large): 더 많은 레이어를 위로

### 3.5 왜 Q4_K_M이 표준인가

- 메모리 1/4 (FP16 대비)
- 품질 95% 유지
- 거의 모든 모델에 GGUF 파일 존재
- 8GB GPU에서 7B/8B를 여유롭게 + 12GB로 14B까지 커버

## 4장. 메모리 종류 — VRAM vs 통합 메모리

### 4.1 일반 PC 구조 (분리형)

```
[CPU] ↔ [시스템 RAM 32GB DDR5]
  ↕ PCIe (느린 다리)
[GPU] ↔ [VRAM 8GB GDDR7]
```

CPU·GPU가 **각자 메모리**. LLM은 GPU에서 돌므로 **VRAM에 다 들어가야 빠름**. 시스템 RAM이 32GB여도 GPU는 못 씀.

### 4.2 VRAM이란

- 그래픽카드 안의 전용 메모리
- 매우 빠름 (GDDR6/GDDR7)
- 용량 제한적 (소비자급 8~32GB)

### 4.3 Apple Silicon — 통합 메모리

```
┌─────────────────────────────┐
│      통합 메모리 (24GB)      │
│   ↕               ↕         │
│  CPU             GPU        │
│  (M4 Pro)      (M4 Pro)    │
└─────────────────────────────┘
   같은 칩 위, 같은 메모리 공유
```

CPU·GPU가 **같은 메모리 풀**. 16GB 통합메모리 = GPU가 약 12~14GB 사용 가능.

### 4.4 AMD Strix Halo — PC 진영의 통합 메모리

2025년 AMD가 출시한 **Ryzen AI Max+ 395** 칩이 PC에 통합메모리 도입. 최대 128GB까지 GPU에서 활용 가능.

### 4.5 NVIDIA Grace Blackwell — AI 전용 통합

DGX Spark의 **GB10 슈퍼칩**은 CPU+GPU+128GB LPDDR5X를 단일 패키지로 통합. AI 추론 전용 설계.

### 4.6 메모리 대역폭 비교

| 메모리 | 대역폭 | 비고 |
|---|---|---|
| DDR5 시스템 RAM | 50~80 GB/s | 일반 PC 메인 (느림) |
| Mac M4 통합 (LPDDR5X-7500) | 120 GB/s | |
| Mac M4 Pro 통합 (LPDDR5X-8533) | 273 GB/s | |
| AMD Strix Halo 통합 | 256 GB/s | |
| Mac M4 Max 통합 | 410~546 GB/s | |
| Mac M3 Ultra 통합 | 819 GB/s | |
| RTX 3060 VRAM (GDDR6) | 360 GB/s | |
| RTX 5060 VRAM (GDDR7) | 448 GB/s | |
| RTX 5070 VRAM (GDDR7) | 672 GB/s | |
| RTX 5090 VRAM (GDDR7) | 1,792 GB/s | 최고 |
| H100 HBM3 | 3,350 GB/s | 데이터센터급 |

→ **VRAM이 통합메모리보다 1.5~3배 빠름**. 작은 모델은 GPU가 압승.
→ **통합메모리는 용량이 큼**. 큰 모델은 Mac/Strix Halo가 유일한 선택.

## 5장. 컨텍스트와 KV 캐시 — 숨은 메모리 소비

### 5.1 컨텍스트(Context)란

LLM이 한 번에 기억할 수 있는 **토큰 양**.

- 1 토큰 ≈ 영어 0.75 단어 / 한국어 1~2 글자
- 8K 토큰 ≈ A4 12페이지

### 5.2 컨텍스트 길이별 활용

| 크기 | 분량 | 용도 |
|---|---|---|
| 4K | A4 6p | 일반 대화 |
| **8K** | A4 12p | 표준 사용 |
| 16K | A4 25p | 보고서 분석 |
| 32K | A4 50p | 논문 1편 |
| 128K | A4 200p | 책 1권 |
| 1M | A4 1,500p | Claude/Gemini 클라우드 |

### 5.3 KV 캐시가 메모리를 먹는 원리

LLM이 토큰 처리 시 **Key/Value 벡터를 메모리에 저장**해 다음 토큰 생성에 재사용. 이게 KV 캐시.

### 5.4 모델 × 컨텍스트별 KV 캐시 (FP16)

| 모델 | 8K | 16K | 32K |
|---|---|---|---|
| 7B/8B | 1 GB | 2 GB | 4 GB |
| 14B | 1.5 GB | 3 GB | 6 GB |
| 32B | 2 GB | 4 GB | 8 GB |
| 70B | 2.5 GB | 5 GB | 10 GB |

### 5.5 KV 캐시 양자화

KV 캐시도 Q8/Q4로 양자화 가능 → 메모리 절반.

### 5.6 실제 필요 VRAM 계산

```
총 메모리 = 모델(가중치)
         + 임베딩/LM Head (~0.5 GB)
         + KV 캐시 (컨텍스트 길이 × 모델 크기)
         + 활성화/작업 버퍼 (~0.5 GB)
         + CUDA 런타임 (~1 GB)
```

예: 7B Q4 + 8K 컨텍스트
= 4.5 + 0.5 + 1 + 0.5 + 1 ≈ **7.5 GB**

→ **8GB GPU에선 빠듯, 12GB GPU 권장**.

## 6장. 모델 크기별 필요 하드웨어

### 6.1 7B / 8B — 입문 기준

- Q4: 4.5~5 GB
- 권장: **VRAM 8GB+** 또는 통합메모리 16GB+
- 대표 모델: Llama 3.1 8B, Qwen2.5 7B, Mistral 7B

### 6.2 14B — 실용적 균형점

- Q4: 9 GB / Q5: 10.5 GB
- 권장: **VRAM 12GB+** 또는 통합메모리 16GB+
- 대표 모델: Qwen2.5-Coder 14B, Phi-4 14B

### 6.3 22B / 27B — 중급

- Q4: 13~16 GB
- 권장: **VRAM 16GB+** 또는 통합메모리 24GB+
- 대표 모델: Mistral Small 22B, Gemma 2 27B

### 6.4 32B — 로컬 GPT-4급

- Q4: 20 GB
- 권장: **VRAM 24GB+** 또는 통합메모리 32GB+
- 대표 모델: Qwen2.5-Coder 32B (GPT-4o급 코딩 능력)

### 6.5 70B — 고급 로컬 추론

- Q4: 40 GB
- 권장: **VRAM 48GB+** (멀티GPU) 또는 **통합메모리 64GB+**
- 대표 모델: Llama 3.3 70B, DeepSeek-R1-Distill-70B

### 6.6 120B / 200B — DGX Spark급

- Q4: 70~120 GB
- 권장: **통합메모리 128GB+** (Mac Studio Ultra, DGX Spark)

### 6.7 405B / 671B — 클라우드 영역

- Q4: 230~370 GB
- 단일 머신: M3 Ultra 512GB만 가능
- 일반적으로 클라우드 또는 멀티 머신

## 7장. GPU 선택 가이드 (Windows / Linux PC)

### 7.1 LLM에서 GPU의 핵심 = VRAM 용량

게임 성능보다 **VRAM 용량이 LLM 가능 여부를 결정**한다.

### 7.2 RTX 5060 8GB — 7B 전용

- 가격: 40~50만원
- 가능: 7B/8B Q4~Q5 (컨텍스트 8~16K)
- 불가: 14B 이상
- 속도: 7B Q4 70~90 t/s

### 7.3 RTX 3060 12GB (중고) — 가성비 끝판왕

- 가격: 30~40만원 (중고)
- 가능: 14B Q4 (컨텍스트 16K), 7B Q8
- 속도: 14B Q4 약 45 t/s
- **신세대 8GB보다 LLM에 유리한 역설**

### 7.4 RTX 5070 12GB — 신품 균형점

- 가격: 90~110만원
- 가능: 14B Q4 매우 빠름 (80~100 t/s)
- 게임도 1440p 쾌적

### 7.5 RTX 5070 Ti 16GB — 14B 여유

- 가격: 130~150만원
- 가능: 14B Q5/Q6 쾌적, 22B Q4 빠듯
- 속도: 14B Q4 100+ t/s

### 7.6 RTX 4090 24GB / 5090 32GB — 32B까지

- RTX 4090: 200~250만원 (단종 임박)
- RTX 5090: 400~500만원
- 가능: 32B Q4 풀로딩, 70B Q3 (5090만)
- 속도: 32B Q4 약 60~90 t/s (5090)

### 7.7 신세대 8GB vs 구세대 12GB의 역설

| 항목 | RTX 3060 12GB | RTX 5060 8GB |
|---|---|---|
| 게임 성능 | 60% | 100% (5060 압승) |
| 7B LLM 속도 | 45 t/s | 75 t/s (5060 빠름) |
| **14B LLM 가능?** | ✅ | ❌ |

→ **14B 이상 노린다면 12GB 구세대가 답**.

### 7.8 멀티 GPU 구성

- RTX 4090/5090 × 2 = VRAM 48~64GB → 70B Q4 풀로딩
- 비용 800~1,000만원, 전력 800W+
- 데이터센터급은 H100 ×8 (H100 1대 5,000만원~)

## 8장. Apple Silicon 옵션 — 통합 메모리의 원조

### 8.1 통합 메모리 = LLM의 새로운 가능성

GPU VRAM에 갇히지 않고 **시스템 메모리 전체를 LLM에 활용**. 70B/192B 모델을 데스크톱 머신에서 돌릴 수 있게 만든 게임체인저.

### 8.2 Mac mini M4 (16/24/32GB)

| 옵션 | 가격 | LLM 가능 |
|---|---|---|
| 16GB / 512GB | 89만원 | 7B 매우 여유, 14B Q4 빠듯 |
| 24GB / 512GB | 130만원 | 14B Q4 여유 |
| 32GB / 512GB | 180만원 | 14B Q5 여유, 22B 빠듯 |

대역폭 120 GB/s, 7B Q4 ≈ 25~35 t/s.

### 8.3 Mac mini M4 Pro (24/48/64GB)

| 옵션 | 가격 | LLM 가능 |
|---|---|---|
| 24GB / 512GB | 209만원 | 14B 고품질, 32B Q4 빠듯 |
| 48GB / 512GB | 280만원 | **70B Q4 가능** ⭐ |
| 64GB / 1TB | 320만원 | 70B Q4 여유 |

대역폭 273 GB/s, 70B Q4 ≈ 5~8 t/s.

### 8.4 Mac Studio M4 Max (64/128GB)

- 대역폭 410~546 GB/s (M4 Pro의 2배)
- 70B Q4: 10~15 t/s (Mac mini Pro의 1.5배 빠름)
- 가격: 64GB 약 360만원, 128GB 약 500만원

### 8.5 Mac Studio M3 Ultra (96/192/512GB)

- 대역폭 **819 GB/s**
- 192GB: **120B~200B 모델 풀로딩**, 405B Q3도 가능
- 512GB: **405B Q4 (230GB)** 단일 머신 가능
- 가격: 192GB 약 800만원, 512GB 약 1,500만원

### 8.6 Mac Pro M2 Ultra (192GB)

- Mac Studio Ultra와 성능 동일 + PCIe 슬롯
- 가격 약 1,000~1,500만원

### 8.7 MacBook Pro M4 / M4 Pro / M4 Max

- 휴대용 LLM 머신
- M4 Max 128GB: 70B 풀로딩 가능, 가격 약 700만원
- 발열·배터리 게이밍 노트북보다 우수

### 8.8 Apple Silicon의 강점·약점

**강점:**
- 통합메모리로 큰 모델 가능
- 조용·저전력 (24/7 운용 적합)
- 작은 폼팩터

**약점:**
- 메모리 대역폭 GPU보다 낮음 (속도 절반)
- CUDA 미지원 (PyTorch는 MPS, llama.cpp는 Metal)
- 학습/파인튜닝엔 부적합

## 14장. 속도(추론 t/s) 이해하기

### 14.1 토큰/초(t/s)가 의미하는 것

LLM이 1초에 생성하는 토큰 수. 한국어 1 t/s ≈ 1~2글자/초.

### 14.2 메모리 대역폭과 속도

```
이론적 최대 속도 = 메모리 대역폭 ÷ 모델 크기

예) 70B Q4 (40GB) on M4 Pro (273 GB/s):
   273 ÷ 40 ≈ 6.8 t/s (실측 5~8 t/s와 일치)
```

### 14.3 사람 읽기 속도 기준

- 사람 평균: 약 5 t/s (한국어 빠른 속도)
- **5 t/s 이상이면 대화 가능**, 10 t/s+ 쾌적

### 14.4 모델·하드웨어별 예상 속도 (Q4_K_M)

| 모델 | RTX 5060 | RTX 5090 | M4 Pro 273GB/s | M3 Ultra 819GB/s |
|---|---|---|---|---|
| 7B | 75 t/s | 250+ t/s | 45 t/s | 130 t/s |
| 14B | ❌ | 130 t/s | 25 t/s | 75 t/s |
| 32B | ❌ | 60 t/s | 12 t/s | 35 t/s |
| 70B | ❌ | △ 10 t/s | 6 t/s | 18 t/s |

### 14.5 컨텍스트가 속도에 미치는 영향

- 컨텍스트 길어질수록 KV 캐시 커지고 attention 계산 증가
- 32K 컨텍스트는 2K 대비 **30~50% 느려짐**

### 14.6 Prefill vs Decode

- **Prefill**: 입력 한 번에 처리 (병렬, 빠름)
- **Decode**: 토큰 하나씩 생성 (순차, 느림)
- t/s 수치는 보통 Decode 기준

### E. 빠른 메모리 계산 치트시트

```
모델 메모리 (GB):
  FP16: 파라미터(B) × 2
  Q8:   파라미터(B) × 1
  Q4:   파라미터(B) × 0.6

총 VRAM 필요 (GB):
  모델 + 1~2 (KV 캐시) + 1 (CUDA 오버헤드)

예) 7B Q4 + 8K 컨텍스트:
  4.5 + 1 + 1 = 6.5 GB → 8GB GPU OK
예) 14B Q4 + 8K 컨텍스트:
  9 + 1.5 + 1 = 11.5 GB → 12GB GPU 필요
예) 70B Q4 + 8K 컨텍스트:
  40 + 2.5 + 1 = 43.5 GB → 48GB+ 필요
```

## 핵심 정리

> 1. **메모리가 곧 LLM의 한계**. VRAM 또는 통합메모리에 모델이 들어가야 한다.
> 2. **양자화(Q4_K_M)**가 표준. 메모리 1/4, 품질 95% 유지.
> 3. **모델 크기 × 0.6 GB**가 Q4_K_M의 빠른 추정치.
> 4. **7B → 8GB GPU**, **14B → 12GB GPU**, **70B → 64GB 통합메모리**가 기준선.
> 5. **Mac은 큰 모델용**, **NVIDIA는 빠른 속도용**, **AMD Strix Halo는 가성비 신흥 강자**.
> 6. **로컬 LLM은 프라이버시·학습 목적**일 때 의미 있고, 가벼운 용도엔 클라우드 API가 압도적으로 합리적.
