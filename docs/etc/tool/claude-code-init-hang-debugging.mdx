# Claude Code 초기화 hang 디버깅

Claude Code 실행 시 아무 출력 없이 멈추거나 `Subprocess initialization did not complete within 60000ms` 에러가 뜰 때, 원인을 체계적으로 추적해 해결한 사례.

## 증상

- `claude --version` → 정상 응답 (바이너리는 살아있음)
- `claude` 실행 → 프롬프트 안 뜨고 무반응
- 네트워크 정상 (`curl https://api.anthropic.com/v1/messages` → 405 Method Not Allowed = 서버 도달 성공)
- 한 프로젝트에서는 되는데 **다른 프로젝트에서만 hang**

## 진단 순서

### 1. 네트워크 확인

```bash
curl -v https://api.anthropic.com/v1/messages
```

`HTTP/1.1 405 Method Not Allowed` 응답이 오면 네트워크는 정상. GET 요청이라 거부당한 것일 뿐, API는 도달 가능.

### 2. 디버그 로그 위치

Claude Code는 `~/.claude/debug/` 폴더에 세션별 로그를 자동 기록한다.

```
%USERPROFILE%\.claude\debug\
├── 88948f78-c414-4545-800d-05cd9b9ef76a.txt  (최신)
├── latest  (심볼릭 링크)
└── b35714c0-693c-47bf-b3c2-b899b6c1a1f7.txt
```

최신 로그 확인:

```cmd
type "%USERPROFILE%\.claude\debug\latest"
```

### 3. 로그 마지막 줄에서 끊긴 지점 확인

디버그 로그가 어디서 끊어지는지가 핵심 단서.

```
2026-04-22T01:31:56.764Z [DEBUG] MDM settings load completed in 31ms
2026-04-22T01:31:56.811Z [DEBUG] mTLS: Creating HTTPS agent with custom certificates
2026-04-22T01:31:56.814Z [DEBUG] Using bash path: "C:\Program Files\Git\bin\bash.exe"
2026-04-22T01:31:56.828Z [DEBUG] Applying permission update: Adding 18 allow rule(s) ...
2026-04-22T01:31:56.870Z [DEBUG] Git remote URL: https://github.com/...
2026-04-22T01:31:56.873Z [DEBUG] [Claude in Chrome] Extension not found in any browser
← 이후 아무 로그 없음 (hang 발생)
```

`Extension not found in any browser` 직후 멈춤. 이 다음 단계는 일반적으로 **추가 디렉토리 워칭/접근** 초기화.

### 4. 프로젝트 로컬 설정 확인

```cmd
type "<project>\.claude\settings.local.json"
```

```json
{
  "permissions": {
    "allow": [...],
    "additionalDirectories": [
      "d:\\Coding\\gangubuy-tax-revised\\.data\\toc\\localtax-law1"
    ]
  }
}
```

`additionalDirectories`에 D: 드라이브 경로 발견.

### 5. 드라이브 존재 여부 확인

```cmd
dir d:\
```

```
장치가 준비되지 않았습니다.
```

**원인 확정.** D: 드라이브가 마운트 안 된 상태인데 Claude Code가 이 경로에 접근하려다 Windows 파일시스템 I/O 응답 없음 → 무한 블록.

## 원인

`settings.local.json`의 `additionalDirectories`에 **이 PC에 존재하지 않는 드라이브 경로**가 포함됨. 다른 PC(D: 드라이브가 있는 데스크톱)에서 사용하던 설정이 **git 동기화를 통해 이 PC로 유입**됨.

Claude Code는 초기화 시 이 경로들을 워칭/접근하려 시도하고, unresponsive drive에서 Windows 파일 I/O는 응답 타임아웃 없이 무한 대기한다.

## 해결

### Step 1: additionalDirectories 비우기

```cmd
notepad "<project>\.claude\settings.local.json"
```

```json
"additionalDirectories": []
```

저장 후 `claude` 재실행 → 즉시 정상 동작.

### Step 2: 재발 방지 (git에서 제외)

`settings.local.json`은 이름 그대로 **PC별 로컬 전용** 파일이므로 git에 올리면 안 된다.

```bash
# 출처: gangubuy-tax-revised 프로젝트
git rm --cached .claude/settings.local.json
echo .claude/settings.local.json >> .gitignore
git add .gitignore
git commit -m "chore: ignore local claude settings"
```

각 명령의 역할:

| 명령 | 동작 |
|------|------|
| `git rm --cached <file>` | git 추적만 중단 (로컬 파일은 유지) |
| `echo ... >> .gitignore` | 무시 목록에 덧붙이기 (`>>`는 append) |
| `git add .gitignore` | 변경된 .gitignore를 staging |
| `git commit -m "..."` | 위 두 변경을 하나의 커밋으로 확정 |

## 왜 같은 Claude Code인데 프로젝트마다 다른가

두 가지 이유:

1. **세션 상태**: 이미 초기화 성공한 세션은 MCP/경로 재검사 없이 유지됨. 인증 만료나 경로 문제가 생겨도 기존 세션은 영향 없음.
2. **프로젝트 로컬 설정**: `<project>/.claude/settings.local.json`은 프로젝트마다 다름. 문제 경로가 들어있는 프로젝트만 hang.

## 디버깅 체크리스트

Claude Code가 실행 시 hang 걸리면 다음 순서로:

1. `claude --version` 응답 여부 → 바이너리 상태
2. `curl https://api.anthropic.com/v1/messages` → 네트워크
3. `%USERPROFILE%\.claude\debug\latest` → 마지막 로그 지점
4. `<project>\.claude\settings.local.json` → 로컬 설정 이상 확인
5. `~/.claude/settings.json`의 `mcpServers` → MCP 서버 행 여부
6. `~/.claude/mcp-needs-auth-cache.json` → 커넥터 인증 만료 여부

## 핵심 정리

> **디버그 로그가 끊긴 지점이 hang 원인이다.** Claude Code는 `~/.claude/debug/latest`에 단계별 로그를 남기며, 무한 대기에 빠진 지점은 **마지막 로그 줄 다음 단계**에서 발생한다. "파일 I/O 무한 블록"은 **존재하지 않는 드라이브나 네트워크 경로 참조**에서 가장 흔하고, Windows 환경에서 특히 잘 발생한다. `settings.local.json`은 PC별 개인 파일이므로 반드시 `.gitignore` 대상이어야 한다.
