# Claude Code 확장 lock 정리 — 터미널 실행과 다른 점

VS Code Claude Code 확장이 IDE에 연결되지 않을 때 `~/.claude/ide/*.lock` 좀비 파일을 정리하는 건 알려진 해법이다([관련 문서](./claude-code-ide-lock-files.mdx)). 그런데 그 문서가 제안하는 **PowerShell 프로필 래퍼는 확장 사용자에겐 작동하지 않는다.** 이 차이를 짚고, 함께 자주 묻는 "VS Code 끄면 대화 기록 날아가나"까지 정리한다.

## 증상과 1차 진단

확장이 연결 안 됨 → `~/.claude/ide/`에 lock 파일이 여러 개 잔존. 어느 게 살아있는 세션이고 어느 게 좀비(죽은 PID)인지 PID 생존 확인으로 판별한다.

```powershell
Get-ChildItem "$env:USERPROFILE\.claude\ide\*.lock" | ForEach-Object {
    $procPid = $_.BaseName
    $alive = Get-Process -Id $procPid -ErrorAction SilentlyContinue
    [PSCustomObject]@{
        Lock   = $_.Name
        PID    = $procPid
        Status = if ($alive) { "ALIVE ($($alive.ProcessName))" } else { "DEAD (zombie)" }
    }
} | Format-Table -AutoSize
```

```
Lock       PID   Status
----       ---   ------
20133.lock 20133 DEAD (zombie)
26774.lock 26774 DEAD (zombie)
50890.lock 50890 DEAD (zombie)
```

전부 죽은 PID면 살아있는 세션이 없다는 뜻 → 전부 삭제해도 안전. 살아있는 게 섞여 있으면 **죽은 것만** 지운다.

```powershell
Get-ChildItem "$env:USERPROFILE\.claude\ide\*.lock" -ErrorAction SilentlyContinue | ForEach-Object {
    if (-not (Get-Process -Id $_.BaseName -ErrorAction SilentlyContinue)) {
        Remove-Item $_.FullName -Force
    }
}
```

## 핵심: 확장 실행은 PowerShell 프로필을 거치지 않는다

[lock 파일 문서](./claude-code-ide-lock-files.mdx)는 근본 대응으로 `$PROFILE`에 `claude` 래퍼 함수를 등록해 실행 시 자동으로 좀비 lock을 청소하는 방법을 제시한다. **하지만 이건 터미널에서 `claude`를 직접 칠 때만 작동한다.**

| 실행 방법 | claude 프로세스 실행 경로 | `$PROFILE` 함수 호출? |
|-----------|--------------------------|----------------------|
| PowerShell에서 `claude` 입력 | 셸이 프로필의 함수를 해석 | ✅ 호출됨 |
| **VS Code 확장 사용** | 확장이 `claude`를 직접 spawn | ❌ 안 거침 |

VS Code 확장은 내부적으로 `claude` 프로세스를 **직접 띄우기** 때문에 사용자의 PowerShell 프로필을 통과하지 않는다. 따라서 확장만 쓰는 사용자에게 프로필 래퍼는 **죽은 코드**다. 등록해봐야 한 번도 호출되지 않는다.

> 교훈: "셸 프로필 자동화"는 **셸을 거쳐 실행될 때만** 유효하다. GUI/확장처럼 프로세스를 직접 spawn하는 실행 경로에는 적용되지 않는다.

### 그럼 확장 환경에서 자동화하려면?

실행 방법과 무관하게 동작하려면 셸 프로필이 아니라 Claude Code의 **hook**(`~/.claude/settings.json`의 `SessionStart` 등)을 써야 한다. 단, hook이 lock을 지우는 시점과 확장이 IDE 연결을 시도하는 시점의 선후는 보장되지 않으므로 만능은 아니다. 자동화가 부담되면 **수동 정리**가 가장 단순하다:

```powershell
# VS Code를 모두 닫은 뒤 한 번 실행
Remove-Item "$env:USERPROFILE\.claude\ide\*.lock" -Force
```

lock 정리 명령 자체는 PowerShell에서 한 줄 치는 것이라, 확장으로 Claude를 쓰는 것과 무관하게 쓸 수 있다.

## VS Code를 껐다 켜도 대화 기록은 안 날아간다

연결 문제로 VS Code를 재시작해야 할 때 "지금 대화가 사라지지 않나?" 걱정이 따라온다. **사라지지 않는다.** Claude Code는 대화 중 `~/.claude/projects/<프로젝트>/*.jsonl`에 **실시간으로 계속 기록**한다.

확인:

```powershell
$proj = "$env:USERPROFILE\.claude\projects"
Get-ChildItem $proj -Directory | ForEach-Object {
    $jsonl = Get-ChildItem "$($_.FullName)\*.jsonl" -ErrorAction SilentlyContinue
    [PSCustomObject]@{
        Project     = $_.Name
        Sessions    = $jsonl.Count
        LastUpdated = ($jsonl | Sort-Object LastWriteTime -Desc | Select-Object -First 1).LastWriteTime
    }
} | Sort-Object LastUpdated -Desc | Format-Table -AutoSize
```

`LastUpdated`가 방금 시각이면 현재 세션이 디스크에 저장되고 있다는 뜻. 다시 켠 뒤 해당 폴더에서 이어가면 된다:

```powershell
claude --continue   # 그 폴더의 가장 최근 대화 바로 이어서
claude --resume     # 저장된 대화 목록에서 골라서 (창 여러 개였으면 각각 복원)
```

## 핵심 정리

> - 좀비 lock은 **PID 생존 확인**으로 판별한다 (`Get-Process -Id <PID>`). 다 죽었으면 전부, 섞여 있으면 죽은 것만 삭제.
> - **VS Code 확장은 PowerShell 프로필을 거치지 않는다.** 확장이 `claude`를 직접 spawn하므로 `$PROFILE` 래퍼 함수는 확장 사용자에겐 호출되지 않는 죽은 코드다.
> - 실행 방법과 무관한 자동화는 셸 프로필이 아니라 Claude Code **hook**으로 해야 하며, 그마저 타이밍 보장이 없으니 수동 정리가 가장 단순하고 확실하다.
> - 대화 기록은 `~/.claude/projects/**/*.jsonl`에 실시간 저장된다. **VS Code를 꺼도 안 날아가며** `--continue` / `--resume`으로 복원한다.
